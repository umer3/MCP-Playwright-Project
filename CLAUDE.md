# Project: Playwright Test Automation (MCP-driven)

Test automation suite built with Playwright, using the Page Object Model.
Tests are generated by exploring the real site through Playwright MCP.

## Project Structure
- Page objects go in `pages/` — one class per page (e.g. LoginPage.js).
- Smoke specs go in `tests/smoke/`, tagged @smoke.
- Regression specs go in `tests/regression/`, tagged @regression.
- Test data (credentials, inputs) goes in `test_data/` as JSON files.
- Shared helpers go in `utils/`.

## Coding Conventions
- Use the Page Object Model. Keep locators and actions in the page class,
  keep assertions in the spec file.
- Prefer stable, user-facing locators: getByRole, getByLabel, getByText,
  getByTestId. Never use brittle CSS/XPath like `.btn-primary` or deep divs.
- Always base locators on what actually exists on the page (read it via MCP),
  not on assumptions.
- Use async/await for all Playwright calls.

## Test Design
- Assert on outcomes (URL, visible text, element state), not on steps.
- Keep it focused: 4–6 meaningful test cases per feature — the happy path
  plus key error/edge cases, not exhaustive permutations.
- Each test sets up and cleans up its own state; tests must run independently
  and in parallel.
- Never hardcode credentials in spec files — read them from test_data/.

## Workflow
- When generating a new feature, first explore the live page, then create the
  page object, then the spec.
- Show file changes as diffs for review before finalizing.
